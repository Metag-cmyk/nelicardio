# NeliCardio — Study-Aid Upgrade Specification

Status: **Draft for review**
Scope: Turn NeliCardio from a point-of-care reference into a specialist-exam study aid while
keeping a fully current, dual-society guideline backbone (ESC primary + AHA/ACC secondary).

Audience for this doc: the maintainer (single-developer, vibe-coded React/PWA codebase).

---

## 0. Decisions already agreed

| Decision | Value |
|---|---|
| Target user | Cardiology residents preparing for the specialist (държавен) exam |
| Locale | Bulgaria, **but not region-locked** |
| Guideline societies | **ESC primary + AHA/ACC secondary**, switchable |
| Units | Both SI and conventional, toggleable (see §7) |
| First deliverables | (1) Guidelines library + coverage matrix, (2) correctness/safety fixes, (3) calculator overhaul, (4) content expansion, (5) **UI/UX overhaul (§9)** |
| Later | Study/quiz engine, spaced repetition, exam simulator (designed here, built after the backbone) |
| This document | Plan/spec only. No code changes yet. |

**Why ESC-primary is justified for the Bulgarian exam:** the Bulgarian specialty curriculum is
explicitly built on the ESC **Core Curriculum for the General Cardiologist** and the European
Board for the Specialty of Cardiology competency requirements (confirmed in the MU‑Varna and
MU‑Plovdiv program documents). So ESC is the exam's native framework, and AHA/ACC is the
comparison layer — not the other way round.

---

## 1. Guiding principles

1. **Cite everything.** Every clinical statement must resolve to `{ society, title, edition, year,
   section/page, class, loe }`. No more "AHA Cardiology Reference".
2. **Society-aware content.** Each recommendation carries an ESC grade and, where it differs, the
   AHA/ACC class/LOE. The UI has a **Society toggle** (ESC / AHA-ACC / Show both).
3. **Versioned guidelines.** Guidelines are data with an edition and a changelog, never a string
   baked into a condition. When ESC publishes a new edition, we bump one record.
4. **No fabricated numbers.** If we cannot source a formula (e.g. real SCORE2 coefficients), we
   label it "illustrative" or remove it. Never ship a made-up risk model as fact.
5. **Fail loudly.** A data-integrity test suite gates the build: missing sources, malformed
   recommendation grades, duplicate ids, and orphaned cross-links all break CI.
6. **Offline-first stays.** Everything is static data + client logic; no runtime network calls.
7. **Educational, not prescribing.** Persistent footer/disclaimer + "verify against primary
   source" affordance on every recommendation.

## 3. Target information architecture

The single flat 5-tab bar does not scale to the study features and hides reference content.
Split the app into two top-level modes with a shared shell (details in §9):

```
REFERENCE  (browse & cite)
  Diagnose      conditions + algorithms (+ Class/LOE badges, + guideline links)
  Guidelines    registry, recommendation tables, "what changed"          (NEW)
  Drugs         medications (+ class/LOE, interactions matrix)
  Scores        rebuilt calculator engine
  Imaging       modalities + real image assets
  Labs          biochemistry + units toggle

STUDY      (practice & retention)                                         (NEW)
  Quiz          vignettes, next-step, class/LOE, score, dosing
  Flashcards    spaced repetition (FSRS)
  Mock exam     timed, blueprint-weighted, score report
  Progress      mastery, weak areas, coverage/readiness

TOOLS
  Coverage      exam blueprint heatmap (covered/partial/missing/outdated) (NEW)
  Command palette (Ctrl/Cmd-K) — global search across all of the above
```

Desktop = persistent left rail with grouped sections. Mobile = bottom bar with 4 primary
destinations + a "More" sheet (never a hardcoded 5-column grid).

**Routing:** every condition, guideline, drug, and score gets a real URL (hash or `react-router`):
`#/condition/stemi`, `#/guideline/esc-2026-hf`, `#/score/grace`. This enables deep links, the
Android hardware back button, shareable links, and history — none of which exist today (navigation
is pure `useState` in `App.tsx`).

Global controls: **Society toggle** (ESC / AHA-ACC / Both), **unit toggle** (SI / Conventional),
**theme toggle** (Light / Dark / System), **text-size**, and the command palette.

## 4. Guideline registry (the backbone)

### 4.1 Data model

```ts
export type Society = 'ESC' | 'AHA/ACC' | 'HRS' | 'EACTS' | 'ESC/EACTS' | 'ACC/AHA' | 'ESC/ERS';
export type RecommendationClass = 'I' | 'IIa' | 'IIb' | 'III';
export type LevelOfEvidence = 'A' | 'B' | 'C';          // ESC
export type AccLoe = 'A' | 'B-R' | 'B-NR' | 'C-LD' | 'C-EO'; // AHA/ACC

export interface Recommendation {
  id: string;
  text: string;
  escClass?: RecommendationClass;
  escLoe?: LevelOfEvidence;
  accClass?: RecommendationClass;
  accLoe?: AccLoe;
  section?: string;   // e.g. "5.2.3"
  page?: number;
}

export interface Guideline {
  id: string;                 // 'esc-2026-hf'
  society: Society[];
  title: string;
  edition: string;            // '2026'
  year: number;
  supersedes?: string[];      // prior guideline ids
  topics: string[];           // blueprint topic ids (§5)
  recommendations: Recommendation[];
  changesSince?: { text: string; kind: 'new' | 'revised' | 'removed' }[];
  doi?: string;
  url?: string;
  verifiedAt?: string;        // ISO date the citation was checked
}
```

## 5. Coverage matrix + exam blueprint

### 5.1 Blueprint model

```ts
export interface BlueprintTopic {
  id: string;                 // 'hf', 'acs', 'arrhythmia.svt', ...
  title: string;
  parent?: string;
  weight: number;             // % of exam, from the syllabus
  conditionIds: string[];
  guidelineIds: string[];
  scoreIds: string[];
}
export interface Blueprint {
  id: string;                 // 'esc-core-curriculum', 'bg-specialty-exam', 'acc-in-training'
  title: string;
  source: string;
  topics: BlueprintTopic[];
}
```

Ship three blueprint presets, all derived from one topic taxonomy:
`esc-core-curriculum` (backbone, since the Bulgarian exam follows it), `bg-specialty-exam`
(Bulgarian конспект), and `acc-in-training` (for the US comparison view).

### 5.2 Coverage computation

Status per topic, computed automatically:

- **Missing** — `conditionIds` empty or no matching guideline.
- **Partial** — condition exists but lacks required fields (no class/LOE, no source, no tools).
- **Outdated** — linked guideline has a newer `supersedes`/edition.
- **Covered** — condition + guideline + class/LOE + at least one tool/score present.

Render as a heatmap with drill-down and an "exam readiness %" per section. This is the concrete
answer to "all current and relevant guidelines represented with all relevant information" — the
matrix makes gaps visible and measurable.

## 6. Calculator engine overhaul

Replace the ad-hoc components with a **declarative scored-instrument engine**.

```ts
export interface Criterion {
  id: string;
  label: string;
  points: number;
  auto?: 'age>=75' | 'age65-74' | 'female' | 'troponin>3x' | ...; // auto-fill from patient
  group?: string;   // for multi-part scores (Duke major/minor)
}
export interface Instrument {
  id: string;
  name: string;
  kind: 'score' | 'formula' | 'dosing';
  criteria?: Criterion[];
  bands: { min: number; max: number; label: string; risk: 'low'|'mod'|'high'; recommendation: string }[];
  sourceRef: string;   // guideline id + section
}
```

Key properties: **typed bands** (no string parsing — fixes B3), per-criterion point values
(supports 2-point items), grouped criteria (Duke major/minor), and patient auto-fill via `auto`.

**Instruments to implement (exam staples):**

- Risk/prevention: **SCORE2**, SCORE2-OP, ASCVD Pooled Cohort, Reynolds, Framingham, CKM staging.
- ACS/ischemia: TIMI (UA/NSTEMI), **GRACE**, HEART, Killip, TIMI-STEMI, DAPT score.
- Arrhythmia: CHA₂DS₂-VASc, **CHA₂DS₂-VA** (ESC 2024 drops sex), HAS-BLED, EHRA symptom, HCM-Risk-SCD,
  Schwartz (LQTS), Shanghai (Brugada), Padua (ARVC).
- HF: H2FPEF, HFA-PEFF, MAGGIC, NYHA, ACC/AHA HF stages.
- PE/DVT: **Wells (PE, DVT)**, Geneva, **sPESI/PESI**, YEARS, Hestia.
- Valvular: Wilkins, STS/ EuroSCORE II.
- Other: SCAI shock stage, NYHA/CCS angina class, DASI/Duke treadmill, CHADS₂.
- **Dosing calculators** (typed, unit-safe): Apixaban, Rivaroxaban (CrCl), Dabigatran, Edoxaban,
  Warfarin (INR), Heparin (ACS/VTE), Enoxaparin, contrast/weight-based, DOAC renal adjustment.

Every instrument gets a unit test with published worked examples. Instruments unsourceable are
removed or explicitly labelled illustrative.

### 9.2 Design principles for a study aid

1. **Content first, chrome last.** Reading surfaces (prose) must be calm, large, and
   sentence-case; decorative gradients/italics reserved for the "at-a-glance" layer only.
2. **Two type roles.** `prose` for reading, `label` for metadata — never one style for both.
3. **Semantic colour.** Brand ≠ danger ≠ recommendation class. Class-of-recommendation gets its
   own fixed palette so the eye learns it while studying.
4. **Everything deep-linkable.** Any view is a URL.
5. **Fast to scan, fast to act.** At-a-glance summary first; tools one tap away; global search
   everywhere.
6. **Accessible by default.** Zoom allowed, ≥44px targets, focus-visible, contrast, reduced motion.

### 9.3 Design language & tokens

Replace ad-hoc Tailwind colours with **semantic tokens** in `@theme` (so dark mode is a one-line
swap), keep the emerald brand from the manifest:

```css
@theme {
  /* surfaces & text (semantic, themeable) */
  --color-surface: #ffffff;          /* dark: #0b1220 */
  --color-surface-raised: #f8fafc;   /* dark: #111a2e */
  --color-border: #e2e8f0;           /* dark: #1e293b */
  --color-text: #0f172a;             /* dark: #e2e8f0 */
  --color-text-muted: #64748b;       /* dark: #94a3b8 */

  /* brand */
  --color-brand: #10b981;            /* emerald — matches PWA manifest */
  --color-brand-ink: #047857;

  /* semantic status */
  --color-critical: #dc2626;
  --color-warning: #d97706;

  /* class of recommendation (fixed, learned while studying) */
  --color-cor-1:   #059669;  /* Class I   */
  --color-cor-2a:  #65a30d;  /* Class IIa */
  --color-cor-2b:  #d97706;  /* Class IIb */
  --color-cor-3:   #dc2626;  /* Class III */
}
```

- **Dark mode**: `class="dark"` on `<html>`, tokens swap; persisted (`theme`), defaults to system.
- **Type scale**: `prose` = 15–16px / 1.6 line-height / max `~72ch`, sentence case, no italic;
  `label` = 11px uppercase tracking-wide for metadata.
- **Numerals**: enable `font-variant-numeric: tabular-nums`; use a mono stack for lab values/scores.
- **Reduced motion**: wrap animations in `@media (prefers-reduced-motion: no-preference)`.

## 10. Study-aid features (phase 2 — designed now, built after backbone)

1. **Question generator** from structured data:
   - Vignette → next best step / diagnosis / drug of choice.
   - "Which class of recommendation?" (uses the new class/LOE data).
   - Score calculation and dosing calculation.
   - ECG/echo/CMR image identification (needs §11 asset library).
2. **Spaced repetition** (FSRS; SM-2 fallback) with per-topic mastery, weak-area dashboard,
   streaks, daily goal, and "exam readiness" tied to the coverage matrix.
3. **Timed exam simulator**: blueprint-weighted, mixed, with score report and rationales.
4. **Case library** authored as structured vignettes (`Question` model with `rationale` +
   `sourceRef`).
5. **Notes/bookmarks/"mark as learned"/dark mode/text scaling.**

```ts
export interface Question {
  id: string;
  type: 'diagnosis' | 'next-step' | 'class-loe' | 'score' | 'dosing' | 'image';
```
